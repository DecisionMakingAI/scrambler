How to Run the Scrambler Project

This guide outlines every major step needed to reproduce the Scrambler DonkeyCar setup — from fresh Jetson Nano installation to model deployment

1. Hardware Setup

  • 2× Jetson Nano (4 GB), Pi Cameras, Logitech F710 controllers, 64 GB microSD cards, RC chassis, and power banks.
  • Connect the CSI camera securely; ensure ribbon cable orientation (contacts facing down toward the board).
  • Test motor and servo wiring before power-on — reversed ESC or servo pins can cause startup errors.

2. Software Installation

sudo apt update && sudo apt upgrade
sudo apt install python3-pip python3-venv git
git clone https://github.com/autorope/donkeycar
cd donkeycar
python3 -m venv ~/venvs/dk
source ~/venvs/dk/bin/activate
pip install -e .
pip install tensorflow==2.9.1 opencv-python

DonkeyCar v4.2.1 and OpenCV were confirmed stable on both Nanos.

3. SSH Setup & Finding IPs

Use SSH for all remote control, data transfer, and debugging. If you don’t know the IP address of your Jetson:

hostname -I

This command returns the local IP(s). You can also find it with:

ifconfig wlan0

Then connect from your host PC:

ssh car1@10.x.x.x     # Password: donkey
ssh car2@10.x.x.x     # Password: 123

To make SSH faster, create an entry in your ~/.ssh/config file:

Host car1
  HostName 10.x.x.x
  User car1
Host car2
  HostName 10.x.x.x
  User car2

4. Data Collection

python manage.py drive

Enable throttle-based auto-recording in myconfig.py:

AUTO_RECORD_ON_THROTTLE = True

All frames and control values are automatically logged in Tub v2 format. Data can be cleaned or trimmed before training:

donkey tubclean data
donkey tubplot --model models/linear.h5

Tip: Record short, distinct sessions (e.g., one behavior per run). Avoid long continuous drives — they’re harder to clean.

5. Training on PC

Move data to your local GPU machine and train using either TensorFlow or PyTorch:

# TensorFlow baseline
python train.py --tub data --model models/linear.h5

# PyTorch behavior model
python train_pytorch.py --tub data --model models/behavior.pt

Why PyTorch? The team found it faster to iterate with GPU support and easier to modify for labeled behaviors.

Once trained, export via ONNX or TorchScript if needed for the Jetson Nano 4GB memory constraint.

6. Deploying the Model

scp models/behavior.pt car1:~/mycar/models/

Edit myconfig.py on the Jetson:

MODEL_PATH = "models/behavior.pt"

Then run the car in inference mode:

python manage.py drive --model models/behavior.pt

Optional: open http://<hostname>.local:8887 in your browser for web control.

7. Quick Notes & Common Pitfalls

  • Camera not found? Ensure sensor_id=0 and sensor_mode=2 in camera.py.
  • Wi-Fi unstable? Set a static IP or reconnect after each boot before launching drive mode.
  • cv2 import errors? Fix with: 
    ln -sf /usr/lib/python3.6/dist-packages/cv2.cpython-36m-aarch64-linux-gnu.so \
       ~/venvs/dk/lib/python3.6/site-packages/
  • Low FPS? Keep resolution ≤ 240×240 at 30 FPS for stable streaming.
  • Training hangs? Delete empty Tub folders or run donkey tubclean first.
  • Throttle sensitivity: Calibrate via joystick mapping (F710 triggers) — misalignment affects labels.
  • Jetson overheating: Use small USB fans or limit GPU frequency to 921MHz for long sessions.

8. Behavior Labeling (Optional)

  • Map joystick buttons (A, B, Y) to behavior states.
  • Record 2–3 short clips per behavior (turning, braking, straight).
  • Keep clips balanced to avoid overfitting one direction.
